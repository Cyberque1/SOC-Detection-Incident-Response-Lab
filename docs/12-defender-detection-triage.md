# Microsoft Defender Detection and Alert Triage

## Objective

Validate Microsoft Defender Antivirus detection and remediation using the harmless EICAR test file, then correlate Defender events with Sysmon process and file-creation telemetry.

## Environment / Tools

- `LAB-ENDPOINT-01` — Windows 11 monitored endpoint
- Microsoft Defender Antivirus real-time protection
- Sysmon Event ID `1` — Process Create
- Sysmon Event ID `11` — File Create
- Microsoft Defender Operational Event ID `1116` — Threat detected
- Microsoft Defender Operational Event ID `1117` — Remediation action applied
- PowerShell for event querying and correlation

Defender status was verified before testing:

- `AntivirusEnabled: True`
- `RealTimeProtectionEnabled: True`
- Security intelligence version: `1.457.226.0`

## Controlled Detection

A standard EICAR antivirus test artifact was created inside the lab at:

```text
C:\Users\User1\Documents\CyberLab\Lab12\EICAR.txt
```

The EICAR artifact contains no real malware and was used only to validate Defender detection and response.

## Sysmon Evidence — File Creation

Sysmon Event ID `11` recorded creation of the test artifact:

- `UtcTime: 2026-08-18 17:54:34.693`
- `ProcessId: 9304`
- `ProcessGuid: {44acc921-98ec-6a84-ef04-000000000e00}`
- `Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
- `TargetFilename: C:\Users\User1\Documents\CyberLab\Lab12\EICAR.txt`
- `User: LAB-ENDPOINT-01\User1`

This established which process created the artifact before Defender responded.

## Defender Detection — Event ID 1116

Microsoft Defender detected the file in real time at approximately the same second as the Sysmon File Create event.

Verified fields included:

- `Name: Virus:DOS/EICAR_Test_File`
- `Severity: Severe`
- `Category: Virus`
- `Path: file:_C:\Users\User1\Documents\CyberLab\Lab12\EICAR.txt`
- `Detection Origin: Local machine`
- `Detection Type: Concrete`
- `Detection Source: Real-Time Protection`
- `User: LAB-ENDPOINT-01\User1`
- `Process Name: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

## Defender Remediation — Event ID 1117

Defender then recorded successful remediation:

- `Action: Quarantine`
- `Action Status: No additional actions required`
- `Error Code: 0x00000000`
- `Error Description: The operation completed successfully.`
- remediation context: `NT AUTHORITY\SYSTEM`

The user context in Event ID `1116` identified the user associated with the detected activity, while Event ID `1117` showed Defender's system-level service performing the quarantine action.

## Process Correlation — Sysmon Event ID 1

The Sysmon Event ID `11` ProcessGuid was correlated back to Sysmon Event ID `1`.

Verified Event ID `1` fields:

- `UtcTime: 2026-08-18 17:39:56.273`
- `ProcessId: 9304`
- `ProcessGuid: {44acc921-98ec-6a84-ef04-000000000e00}`
- `Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`
- `User: LAB-ENDPOINT-01\User1`
- `IntegrityLevel: Medium`
- `ParentProcessId: 5892`
- `ParentImage: C:\Windows\explorer.exe`

The PowerShell process had been running for roughly 14.5 minutes before creating the EICAR file. The matching PID and ProcessGuid tied the later file creation to that exact process instance despite the time gap.

## Reconstructed Timeline

```text
explorer.exe
      ↓
PowerShell process starts
Sysmon Event ID 1
PID 9304 / matching ProcessGuid
      ↓
PowerShell creates EICAR.txt
Sysmon Event ID 11
      ↓
Defender real-time protection detects EICAR
Defender Event ID 1116
      ↓
Defender quarantines the file
Defender Event ID 1117
      ↓
No additional action required
```

## Analyst Finding

This was a **true-positive security-product detection generated by intentional benign test activity**. Microsoft Defender detected the EICAR test signature through Real-Time Protection and successfully quarantined the artifact. Sysmon independently recorded the PowerShell process and the file creation, allowing the Defender alert to be correlated with endpoint telemetry.

For a real SOC incident, successful quarantine would not by itself end the investigation. Additional scoping would still be required to identify related processes, files, network connections, persistence, or repeated detections.
